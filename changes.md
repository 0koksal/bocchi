- Map mods from the marketplace no longer crash the game after Apply: LTK Manager reads `.modpkg` natively, but Bocchi converted every package to `.fantome` first, and that conversion kept only WAD chunks — the package's `game_data.yaml`, which holds the map's bin and material edits, was dropped, so the map loaded without them and the game exited. A `.modpkg` now reaches LTK Manager untouched, and the classic cslol path keeps the converter, which now carries such declarations as `META/game_data/<layer>/...`
- A skin that was repaired once is repaired again when the same original is re-downloaded later: the pre-Apply health pass found the earlier report (stored under the original file's hash) and skipped the repair even though the archive on disk was the unrepaired original, so the broken base-skin data was applied and the skin did not show up; the pass now skips only when the archive's own hash equals the repair's output hash
- Map mods from the marketplace now download instead of failing with "modpkg chunk exceeds 64 MiB limit": a Summoner's Rift map geometry is about 90 MiB once decompressed, so the package reader and the health scan now accept up to 256 MiB per chunk (only the read limits grew; repairs keep their tighter bounds), the scan reads that payload instead of skipping it, and a map mod no longer reaches "needs attention" over a payload it could not inspect
- Show Skin Names In Game now works on a client in any language: LTK Manager applies the names only to `data/menu/<client language>/lol.stringtable`, but the game keeps that table at `data/menu/en_us/lol.stringtable` in every language wad, so on a non-English client it looked for a chunk the game does not have and the names never appeared; an English client still gets the small metadata-only string-overrides mod, any other language gets the game's own table patched inside the generated mod (which LTK Manager accepts, as it only refuses a table for a language wad it sees installed), and a client that has the English wad next to its own language is left alone; the setting is on by default again
- Skins download and champions resolve on a non-English client: champion lookups were hard-wired to `en_US`, and a repository URL was built from the client's localized display name ("Nunu y Willump"), so on a localized install the lookup came back empty and the download pointed at a folder the repository does not have; lookups now start from the client's language and fall back to every language already loaded, and the repository folder is taken from the champion's Data Dragon key
